# 怎么写 Listener 的产品功能

产品功能文档回答三件事：**这是什么、用户怎么用、现在承诺到哪**。
它不是营销页，也不是源码地图。

## 别人怎么写

看过 Wispr Flow、Superwhisper、讯飞输入法、Plaud Note、Limitless Pendant。
能学的是结构，不是口号。

| 做法 | 谁在用 | Listener 要不要学 |
| --- | --- | --- |
| 先写用户动词，再写功能名 | Wispr：Speak / Refine / Personalize | 要。按「说进去、整理、设备、保护、本地」分组，不按 `coordinator` / BLE 模块分组 |
| 三步讲清主路径 | Superwhisper：说话 → 转写 → 整理 | 要。Listener 是：开始 → 说话 → 文字回到光标 |
| 每个功能写清何时可用、平台差异、上限 | Wispr 帮助中心 | 要。Windows BLE、macOS 麦克风、1.0.5 边界都写进功能本身 |
| 硬件产品先写手上的动作和灯 | Plaud / Limitless：按下、灯、结果 | 要。EC11、KEY、PWR/BLE/REC/AI 是产品语言，不是附录 |
| 数字必须有出处 | 讯飞「1 分钟 400 字」带检测编号 | 要。没有实测来源就不要写准确率百分比 |
| 「AI 写得完美」「任何环境 100% 隔离」 | Wispr 营销句 | **不要。** 和已验收的 1.0.5 合同冲突 |

Wispr 把听写写成「替你改文章」；Plaud 把设备写成「会后纪要」。
Listener 的主工作不是这两件。主工作是：**桌面上的语音输入**——话说完，文字出现在当前光标。

## 本仓库怎么写

1. **先写用户看见的东西。** 胶囊状态、灯、按键、插入位置。不要把 F13、GATT、Resource ID 写进产品功能。
2. **一个功能一件事。** 标题用用户动词或结果，不用内部模块名。
3. **每条功能四个字段：** 做什么、怎么用、你看到什么、现在的边界。
4. **状态用产品词。** Ready / Recording / Transferring / Processing / Done / Error / Recovery。不要发明第二套状态名。
5. **硬件和软件写在同一条主路径里。** 键盘负责开始/停止和灯，Type 负责转写和插入。拆成「固件功能」「软件功能」两套目录会让人以为要买两个产品。
6. **边界写在功能旁边，不藏在文末免责声明。** 1.0.5 是日常输入基线；声纹通例化、真人多人干扰泛化留到 1.0.6。
7. **没实现的当计划，不当功能。** 远程 Marketplace、系统输入法、100% 旁人过滤，未验收就不写进「能做什么」。
8. **工程地图继续独立存在。** `docs/features/*.md` 和固件 feature map 给 agent 和实现用；产品文档给人和验收用。两边可以互相链接，不要互相复制。

## 不要写进产品功能的内容

- 源码路径、测试命令、GPIO 编号、HID 兜底键位
- 未带出处的准确率、速度、续航数字
- 把声纹写成登录、门禁或法律身份认证
- 把一次受控干扰通过写成任意房间都可用
- 把安装包 SHA、OTA 哈希当作功能介绍（那些放发布说明）

## 改文档时先问

1. 用户不打开设置页，能不能用一句话说清这个功能？
2. 第一次失败时，他该按哪个键、看哪盏灯？
3. 1.0.5 是否真的已经交付？还是 1.0.6 计划？
