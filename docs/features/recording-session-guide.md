# 录音会话、自动结束与干扰处理

这份说明解释 Listener Type 一次录音从开始到文字插入之间发生什么，以及在有
旁人说话、电脑播放声音或主人自然停顿时应该如何理解界面表现。它描述的是
1.0.5 的用户可见边界，不是身份认证或录音取证协议。

## 一次会话的完整路径

Listener Type 把一次录音视为一个有开始、有结束、有最终文本的独立会话：

```text
待机 → Recording → Transferring/Transcribing → Processing → Done
                                      ↘ Error / Cancelled
```

1. **开始**：快捷键、EC11 单击或已启用的自动唤醒建立一条新会话。开始前请把
   光标放进目标输入框。
2. **Recording**：电脑麦克风或 Listener BLE 正在收音。胶囊和设备 REC 灯表示
   录音边界，音量变化只代表收到的信号，不代表主人判断分数。
3. **Transferring/Transcribing**：你按停止键、固件自动停录或软件判定结束后，
   音频继续完成传输和识别。此时不要连续按开始键，也不要拔掉设备。
4. **Processing**：应用选择最终文本、应用 Raw/Light/Structured/Formal 或翻译
   规则，并准备插入。这个阶段看到短暂的 AI 灯或 Processing 胶囊是正常的。
5. **Done**：文字已插入原光标位置，或已经写入剪贴板等待手动粘贴。目标应用拒绝
   自动输入时，剪贴板是有意保留的安全回退。
6. **Error / Cancelled**：错误会保留可操作提示；按 Esc 主动取消时，不应把半截
   文字插入目标应用。

## 如何结束录音

1.0.5 默认是 Toggle 模式：按一次开始，再按一次停止。自然停顿不会立即丢掉会话，
但也不要把“停顿”当成手动停止的替代品。需要完整保留最后一句时，建议说完后
等待约一秒，再按停止键；看到 Transferring/Transcribing 后再等待 Done。

自动结束只根据当前会话中主人语音的活动和已确认的音频边界工作：

- 旁人的持续说话不应单独把主人会话延长；
- 短暂的不确定声纹窗口会等待后续证据，不会马上删除已经确认的主人前缀；
- 已经进入停止/处理阶段后到达的旧片段，不应重新开启下一次录音；
- 句子是否有句号不是结束条件，完整的短句也可以在没有明显标点时结束。

如果你要说多段内容，使用同一次录音并在段落之间自然停顿即可。不要在每个短句
之间反复按开始/停止，这会制造多个独立会话并增加蓝牙传输和 Provider 延迟。

## 自动唤醒和主人语音

打开「设置 → 录音 → 检测到人声后自动开始」后，设备先等待唤醒词，再决定是否
创建正式录音会话。默认唤醒词是“开始录音”。自动唤醒有三个可见边界：

- 只听到环境声不会创建正式正文；
- 唤醒词本身不是正文，正文从唤醒词之后开始；
- 没有声纹时，能正确说出唤醒词的人可能触发会话；开启“仅本人语音自动开始”
  并完成三遍声纹录入后，系统会优先使用主人证据。

声纹录入只生成本机模板，录入原始样本不会作为普通历史录音长期保存。声纹是
“是否尝试启动和保留主人语音”的输入保护，不是登录、门禁或法律意义上的身份
认证。距离太远、多人同时说话、麦克风被遮挡时，应关闭自动唤醒或靠近设备重试。

## 旁人、电脑播放和主人自然停顿

干扰处理不是把所有声音从音频里物理删除，而是让同一会话的几条证据共同决定：

1. 哪些文字属于当前主人前缀；
2. 哪些声音只能作为旁人/不确定尾部；
3. 什么时候主人已经安静足够久，可以结束；
4. 最终插入时使用哪个候选文本。

因此测试时应区分三种情况：

| 情况 | 预期体验 |
| --- | --- |
| 主人自然停顿后继续说 | 前面的主人文字保持，继续说的内容仍属于同一会话 |
| 电脑扬声器播放旁人语音 | 旁人内容不应进入最终正文，也不应单独延长主人自动结束 |
| 主人和旁人同时说话 | 可能出现不确定尾部；系统优先保留已确认主人前缀，结果应人工复核 |

1.0.5 的稳定承诺是受控环境下的输入保护，不是所有房间、距离、口音和重叠说话
条件下的 100% 分离。验收时请同时检查胶囊预览、最终插入文本和结束时机；只看
其中一项不能代表完整成功。

## 推荐的验收顺序

每次更换 Provider、声纹或设备固件后，用下面的顺序做短验收：

1. 在记事本建立光标，关闭其它会抢全局快捷键的软件。
2. 做一条主人单句：开始 → 说话 → 自然停顿 → 继续一句 → 停止，确认两句都在最终
   文本里。
3. 做一条主人 + 电脑播放干扰：播放短的人声，主人在播放前后各说一句，确认
   最终文本保留主人内容且不把明显旁人句子插入正文。
4. 重复一次短句，确认旧会话结束后不会自动再次 Recording。
5. 最后检查剪贴板、历史记录和 Done 胶囊；不要只根据实时预览判断最终结果。

如果第二步失败，先切换为电脑麦克风并关闭自动唤醒，判断问题属于设备/蓝牙还是
ASR/Provider。只有稳定通过单人路径后，才有意义测试干扰路径。

## 出现问题时应记录什么

从「设置 → 关于」导出诊断包，并一并记录：

- Listener Type 版本、固件版本和输入源；
- 是快捷键、EC11 还是自动唤醒开始；
- 胶囊最后显示的状态（Recording、Transferring、Processing、Done 或 Error）；
- 主人说话、停顿、旁人/播放声音出现的大致时间顺序；
- 最终插入文本和剪贴板文本是否一致；
- 是否只是预览缺字，还是最终文本也缺字。

诊断包用于定位会话、蓝牙和 Provider 状态，不应包含 API Key。不要在 issue 或群聊
里粘贴凭据、完整私人录音或未脱敏的转写正文。
