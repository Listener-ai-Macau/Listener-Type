## 现在还剩什么问题

**不稳定的根：进门那一关。**

- 窗口里本地听清口令 → 后面预览、上屏、去语气词都好  
- 窗口里口令没有、声纹也不是你（`phrase_signal=None` + `enrolled_non_match`）→ 整段拒，像没唤醒  

所以「前两次可以、以后不一定」是真的：不是功能随机坏，是 **隐藏 4 秒窗口有时套住「开始录音」，有时套不住**。套不住时按合同必须拒，再接受会误唤醒，会把现在这版体验打回去。

其余已按合同修好、成功时不应再出现：

- 预览被 PCM 空包冲掉  
- 句号当说完、1 秒掐句  
- 隔离把已显示正文封成 Empty  
- 去语气词把逗号收成句号  
- 结束时正文当 wake-only 丢掉  

云端用字（三点→3点、「再」丢失）不是主机合同。

## 成功路径 vs 失败路径（修之前先看这个）

| | 成功 | 失败 |
|---|---|---|
| 唤醒 | live `ExactStart` / `LocalTranscript` 约 1.7～3s | 终端 `None` + `enrolled_non_match` |
| 预览 | 激活后很快涨字 | 胶囊空着，或窗口结束才新开录音、云端重连 |
| 上屏 | `partial_preview_recovery`，字数≈胶囊 | `authority=empty` 或 cancel 丢账本 |
| KWS | 经常仍是 `kws_hit=false`，不靠它 | 同样不靠它 |

关键词模型即使成功唤醒也经常打不中。现在能唤醒，靠的是 **本地确认在 3 秒窗口里听到完整口令**。

## 怎么修才不是试错

1. **先打开成功那次日志**，记下：live 还是 terminal、第几秒 ExactStart、第一笔 visual 的 elapsed、上屏 authority 和字数。  
2. **失败那次只对比这几列**。差在进门（拒）就不要去拧结束钟、隔离、去语气词。差在上屏 empty 就不要去放宽唤醒。  
3. **一次只堵一条已经发生的洞**，而且不能让成功表里的 live 流式路径变慢（终端补听加等待、续录重连，都试过，owner 觉得比基线差，已撤回）。  
4. **已显示的字是地板**，过滤只能少加尾巴，不能把胶囊上的字裁没。  
5. **不要接受「谁都不是」的窗口** 来换唤醒率。

试过错、不要再叠：

- 离线 KWS 等待从 0.5s 加到 1.2s → 预览慢、吞字，已 revert  
- 续录发 24 字状态文案 / 取消插入那一刀 → owner 要回基线，已 revert  

留着、成功时靠它们：

- PCM 空包不冲预览  
- 开口句 2.5 秒结束钟  
- 胶囊字上屏地板  
- 前几次 Absent 不关 3s/5s 确认梯子  
- 终端声纹认出你也开录  
- 结束时迟到的正文不丢  
- 去语气词保留逗号；预览不边出边抠嗯呃  

## 以后若要不稳变稳

已做、仍要求有词：

- Type：actor 空闲时才顶掉卡住的旧 WakeCandidate（突然全灭），不抢正在听写。
- 固件：隐藏窗口拒一次后 cooldown 400ms（原 1200ms），少吃掉紧接着的「开始录音」。

不能做：接受 `phrase_signal=None` + `enrolled_non_match`。回归仍看 live 1.7～3s、预览跟着涨、上屏≈胶囊。
