## 已确认的通用修复

- 固件先完整发布 preserve/handoff 状态，再发布 AFE boundary；实际键盘交接不再丢一个内部缓冲周期。
- 云端滚动窗口重复携带唤醒前缀时，合并器按共享终端前缀累积分句，并只替换仍在增长的活动分句。修复不含测试句文字特例。
- 去除独立的“嗯/呃”等语气词时保留分句之间的逗号、句末标点、引号、括号和换行；关闭功能时保持原文。
- 已建立本会话 owner 后，新鲜麦克风语音与 provider-pending 正文可在声纹暂时 Uncertain 时续期结束钟；明确 NonTarget 和云端把房间声音合并进旧 speaker id 的增长仍不能续钟。已过滤的旁人终稿不会被更长的旧预览重新覆盖。
- 普通稳定预览不依赖云端先补句号，静音约 1 s 后结束；只有明确停在“然后、但是、因为、所以”等续接词时保留 2.5 s 思考窗口。

## 尚未采用的方案

同一段失败 PCM 再请求一次云端，曾从缺句恢复成完整三段，但同时新增了错误词。按“字数/说话时长”判断稀疏结果会把正常的短句或慢速讲话也送入第二轮，增加数秒等待；“第二次更长”也不能证明第二次更正确。因此该实验代码已撤回，没有进入安装候选。

`force_to_speech=1000 ms / end_window=500 ms` 在同一键盘 PCM 的直接云端三轮对照中三次都返回完整三段，优于 `1000/1000` 的一成两败；但安装版真实链路连续三版分别出现分句乱序和整句重复。原因是声纹过滤、显示预览和最终 session ledger 仍有多个状态入口，单独改善 provider 终稿会暴露重复写入。三个失败候选及其局部合并实验已经撤回，日常安装恢复为上面的 `9161995F…` 稳定候选。下一次不得继续在滚动合并函数外围加启发式，必须先把预览、声纹过滤和终稿收敛到单一带版本的 transcript ledger。

同一份 `e9a0…` 键盘实收 WAV 的本地 Paraformer 对照在 92 ms 内得到“开始录音先检查键盘文再确认语音输入呃然后结束这句话”，独立找回云端漏掉的“再确认语音输入”；成功会话 `d261…` 的本地对照也包含该段，耗时 83 ms。两个会话各取 2–8 s、3–9 s 两个重叠窗口，四次 36–39 ms 推理都包含“再确认语音输入”，而相邻噪声在“文/呃/饿/乐/截”之间变化。该证据证明本地模型可用于发现漏句，但不能用本地整句覆盖云端。原始对照记录在任务工作区 `work/filler-local-shadow-probe.json`。

下一步只在独立识别证据能定位云端缺失区间时恢复正文：本地 shadow 与云端同时处理同一份 PCM；两者已有文字需按顺序稳定对齐；只允许补回夹在两个共同锚点之间的短缺口；检测到旁人、改写或无右侧锚点时保持云端结果。正常完整终稿不增加网络重放和结束延迟。
