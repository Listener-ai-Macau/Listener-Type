## 固定答案，再运行产品

每个场景在运行前固定原始音频及 SHA-256、本人应说的正文、不得混入的尾句、输入方式、停顿位置和计时起点。答案只能来自原始口述或生成素材的脚本，不能从现有 ASR 输出反推。正常停顿、语速、距离等变体可以增加，不能为绕过失败修改答案。改变答案必须记录原值、依据和原因。

实际链路是电脑外放 → 键盘麦克风 → 固件 → BLE → 已安装 Type → 最终输出。每轮保存 Type/固件身份、素材身份、会话 ID、最终文字、预览、停止及完成时间。日志解释根因，不能替代最终文字。合成声音用于可重放对照，不代表真实双人插话或远场电视覆盖。

## 如何判定

- 本人正文完整与旁人尾句是否混入分开报告，联合通过同时要求两者成立。空输出和把本人一并过滤掉都失败。
- 正文按预先约定的 Unicode、空白和标点规范化比较，不用相似度放过首字、末字、句子遗漏；同音错误单独记录，不能补词骗过判定。
- 每个场景保留所有轮次。修复原失败后至少连续三轮，再跑正常长句、1.5 秒句中停顿和手动操作对照；一轮失败不能被后面的成功覆盖。三轮仅是初步回归门槛，不表示已证明长期可靠。
- 固定失败素材通过后，再用未用于调参的新句子和不同停顿位置交叉验证；最后补现场真人。固定录音、音量、距离的通过不能扩展为所有房间和背景声音都可靠。
- 首预览从正文起声计时；结束延迟从最后一次实际文字变化计时。旧日志只有字数变化，不能充作这两项精确验收。
- 多个完成会话不能自动选第一条；预览、STOP、历史必须属于同一会话。缺失、串轮或版本不匹配记为未验证，不能算通过。
- 上屏检查使用用户关心的实际最终输出，不要求打开记事本。结果采集模式不进行真实输入时，必须注明上屏未验证。
