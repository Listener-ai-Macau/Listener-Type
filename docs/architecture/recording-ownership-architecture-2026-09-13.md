# 录音、说话人和最终文字的统一结构

当前问题可以修，但不适合继续叠加长度规则和全局声纹阈值。现有实机已经证明两种独立失败：说话人过滤没有排除旁人；过滤排除后，正文恢复又把原始旁人段带回。它们需要在同一套归属结构中解决。

## 六层职责

1. **固件传输层**：负责会话身份、PCM 顺序、重放和真实终帧，不判断文字属于谁。
2. **唤醒准入层**：只决定是否创建正式听写会话。口令证据和可选声纹证据分别记录；超时不能自动变成阳性。
3. **录音生命周期层**：只维护 Listening、Stopping、Transcribing、Done/Rejected；自动结束消费本人语音时钟和物理尾包状态。
4. **识别证据层**：同时产出原始文字、带时间的 speaker 行、局部声纹窗口和 provider final，不直接执行最终插入。
5. **文字归属层**：维护 `provisional_visual`、`authoritative_owner`、`explicit_non_owner` 三类信息。显示可以快，最终只能消费权威本人文字。
6. **产品提交层**：一次选择最终权威来源，执行口令清理、语气词/标点、风格或翻译，随后插入和写历史；下游不能再发明第二套恢复来源。

## 必须保持的规则

- `provisional_visual` 只能改善预览速度，不能成为最终正文、正文恢复或插入依据。
- 本人正文恢复必须说明被恢复的音频时间段，以及覆盖该段的本人证据；不能用“整段声纹曾经稳定”恢复后续新 speaker 行。
- provider 稳定的新 speaker 行被排除后，恢复逻辑必须默认保持排除。只有时间覆盖同一行的强本人证据才能推翻。
- 已确认的本人正文是保留底线；未确认的显示高水位不是保留底线。
- 自动结束以最后一次已确认本人语音、句子状态和真实尾包交接为依据；旁人不得单独续时，显示文字不得独立续时。
- A/B（漏唤醒/误唤醒）、C/D（过早结束/不结束）、E/G（本人完整/旁人排除）必须成对验收。

## 发布分层

- **稳定核心**：手动快捷键或旋钮开始、自动/手动结束、电脑麦克风或 BLE 音频、最终文字处理与插入。
- **受限能力**：自动语音唤醒、声纹和多人干扰。只有固定回放与真实现场连续通过后，才从受限能力提升为稳定能力。
- README 和 Release 必须写当前分层，不能把受控单例通过写成任意环境保证。

## 下一项最小修复

使用实际短句会话 `821bf512-fde3-4156-8384-8393d8d22fe7`：provider speaker 0 正文结束于 5702 ms，speaker 1 从 6422 ms 开始。过滤已留下本人正文，但 `provider_owner_recovery` 又恢复整段。先把这一时间线固化为通用回归，要求恢复证据与被恢复行时间重叠；同时加入真人本人被 provider 错分 speaker-id 的保护样本。两类一起通过才装机。

这项修复不改全局声纹阈值，不改变预览速度和自动结束时钟。若不能同时保住本人正文与排除旁人，保留当前日常体验基线，把多人能力继续标为受限。
