# 成熟语音系统与 Listener 声纹/抗干扰调查（2026-09-13）

结论：目前不能把失败归结为 CAM++ 模型差，也不能宣布模型没有问题。已经有直接证据证明音频交付、终稿路径和文本融合会影响结果；声纹模型、分离模型和它们的接入方式必须分别验证。本次先研究公开方案，撤回有吞正文风险的身份实验，不改声纹阈值或替换模型。

## 一手资料与适用边界

| 公开方案 | 已公布机制 | 对 Listener 的启示与边界 |
| --- | --- | --- |
| [Apple，Voice Trigger System for Siri，2023-08-11](https://machinelearning.apple.com/research/voice-trigger) | 高召回流式候选检测、高精度复核、SpeakerID、面向设备的语音检测分层；声纹既看短唤醒词，也利用后续完整语音作更可靠判断 | “有唤醒词”“是登记本人”“正在对设备讲话”不是同一个判断。不能把短窗口不确定直接解释为旁人。文章描述当时实现，不等同所有当前 Apple 设备内部算法；长篇自由听写也不能照搬助手指令语法限制。 |
| [Apple，HomePod 远场处理，2018-12-03](https://machinelearning.apple.com/research/optimizing-siri-on-homepod-in-far-field-settings) | 所述六麦克风系统结合回声消除、去混响、噪声抑制、竞争说话人分离，再用唤醒信息选音频流；在真实设备、不同声源和摆位下联合测唤醒与文字错误 | 抗电视人声是音频前端、分离和选择的组合问题，声纹并不能直接清除混合波形。六麦克风空间信息不能假定 Listener 当前单声道输入也具备；设备自身外放回声与外部电视不是同一种参考信号条件。 |
| [Google，VoiceFilter-Lite，2020-11-11](https://research.google/blog/improving-on-device-speech-recognition-with-voicefilter-lite/) | 用目标声纹辅助流式特征过滤；非对称训练损失更惩罚过度抑制，并按噪声类型调整强度；评价最终 ASR 词错率及单人场景是否退化 | 不吞本人比把分离声音做得安静更关键。该研究当时仅英语实验，不能把报告效果外推到 Listener 中文，也不是可直接替换当前云端音频接口的现成模型。 |
| [Google，Unified End-to-End Speech Recognition and Endpointing](https://research.google/pubs/unified-end-to-end-speech-recognition-and-endpointing-for-fast-and-efficient-speech-systems/) | 研究联合识别与结束预测，并同时评估词错率、结束延迟 | “更快结束”必须带着不截断指标一起优化。论文结果不证明我们缩短静音阈值就能得到同样效果。 |
| [3D-Speaker 官方仓库](https://github.com/modelscope/3D-Speaker) | 提供 CAM++、ERes2NetV2 等声纹模型；中文通用 CAM++ 模型来源和多数据集基准公开；说话人分段另有 VAD、分段、聚类、可选重叠检测组合 | CAM++ 是有公开训练与评测基础的模型，不能凭产品失败就称其劣质。公开基准不是当前 ONNX、短窗口、键盘收音、本人声纹模板的准确率。ERes2NetV2 可作为有限对照候选，尚未在本机比较，不能推荐直接换装。 |
| [WeSep 官方仓库](https://github.com/wenet-e2e/wesep) | 目标说话人提取工具包 | 识别人和提取声音是不同任务；上游工具包的能力不能等同本地三秒 int8 导出物效果。 |

## 当前代码和实机证据

- `src-tauri/src/speaker_verification.rs` 配置中文 16 kHz CAM++，模型 SHA F682B514C05D947EE3FA91CD6EC6C5C7543479A128373FA29B1FAEDCCD21FD11。登记样本与会话片段的来源/长度必须随评分记录，不能只看一个相似度。
- `src-tauri/src/asr/target_speaker_extraction.rs` 使用 `wesep-bsrnn-voicefilter-3s-int8.onnx` 和独立 WeSep speaker encoder，三秒块；不是 CAM++ 一项模型包办抗干扰。三秒块处理与末尾等待属于延迟调查项，不能断言全部预览慢都由它导致。
- 已修复 STOP 发出后过早给云端发最后帧：旧会话 74b7ab15-0fb4-41aa-9b7b-9cbf1287c53e 的归档比送云多 45664 字节，约 1427 ms。这个错误与换声纹模型无关。
- 已修复自动结束直接拿预览提交、绕过等待云端终帧与本人终稿过滤。14D3D84E 候选七轮实机都具备完整字节交付和覆盖对应时长的云端终帧，但只有 2/7 正文判定通过；不能把传输通过说成抗干扰已好。
- 06F5BC71 身份实验九轮中正文 4/9 通过，5/9 失败，9/9 有完整音频交付和云端终帧；一个无口令负例观察 46.05 秒未进入正式录音/输出，但没有覆盖“登记本人无口令”分支。
- 06 实验会话 59e1f309-f136-47b8-9acf-6b0ca07cd0fa：云端原文含本人正文和旁人尾句，`speaker_filtered_result` 只剩“开始录音。”，`merged_candidate` 又带回旁人预览，最终只输出旁人文字。因此目标身份/过滤/预览融合组合失败已经确定；仅这一轮不能分离证明是 CAM++、WeSep、模板还是单个决策函数造成。该实验撤回，保留前两项交接修复。
- 当前干扰量按有效块累计残差能量/混合能量判定；长句后短尾音被全局平均稀释是待验证假设，不是已确认根因。不能直接改为任意单块超过阈值就强滤，过去有误删本人风险。
- 同一电脑扬声器依次播放不同合成声音，可复现软件失败，但不能代替本人真实声纹准确率、不同方向的真人双说话人验收；已核对测试使用不同 TTS voice，不能把失败素材重新解释成同一个说话人。

## 下一步最小成本验证顺序

1. **冻结安全候选与固定答案。** 失败实验保留源码、包和全部失败记录；日常候选撤回实验，不开启新增过滤。先保存当前可重放的原 PCM、会话 ID、模型 SHA、固定本人正文和旁人区间。
2. **先做离线分层对照，避免反复安装。** 使用同一份键盘 PCM 对比原音频、既有声纹归属、分离音频、最终文本融合。记录每段本人保留、旁人泄漏和延迟；先确定错误进入哪层。只有分离音频确实删掉本人时才追查分离模型/目标 embedding；如果音频/云原文正确而合并文字错，先修状态与合并。
3. **模型能力对照与接入对照分开。** 声纹比较固定模型在不同可用语音时长、登记模板与实际唤醒模板下的本人/旁人分布；不将 TTS 登记到用户永久声纹。若现有模型分不开，再只比较一个中文候选模型，采用独立说话人/录音留出集，比较相同本人误拒水平下的旁人误接、计算延迟和 CPU。分离模型另比较浮点/当前 int8 及块边界（在可获得匹配原始模型时），不得把模型和规则一起换后猜原因。
4. **按场景修程序。** 顺序接话重点验证本人活动结束、说话人变化和待定尾段；真正重叠讲话才考查分离是否改善最终文字。低置信度不能作为硬删本人依据。原始混合音频预览与慢速过滤结果的合并必须明确时序，避免先提交旁人再因“不回撤”永久保留。
5. **源码改动通过对照后才安装实机联合验收。** 同时记录唤醒漏检/误触发、本人缺字、旁人字数、停顿误截断、正文起声到首预览、最后预览到完成。没有新改动不重复全套构建；双真人和电池/物理按键项目保持未验证，不能用朗读脚本代替。

不变的产品优先级：保住唤醒；不截断；不吞本人；再降低旁人泄漏和等待。保留现有三段声纹登记，不因为对照 Siri 而擅自增加用户登记步骤。研究尚未证明应当换模型，当前决定是先隔离测量模型与接入损失。
