# Listener Type 1.0.5: commercial-readiness boundary

This page is for maintainers and people evaluating whether the current product
is ready to sell or distribute. It is intentionally more conservative than a
marketing page.

## What a buyer is getting

Listener Type 1.0.5 is a local-first desktop voice-input product. The value is
the complete loop: press a key or use the Listener keyboard, speak naturally,
receive usable text, and continue working in the application that already has
focus. The product also provides configurable output modes, provider choice,
clipboard recovery, hardware feedback, and a visible recording/processing
state.

The current baseline is strongest for:

- Windows desktop dictation with the Listener BLE keyboard.
- Computer-microphone dictation on Windows or macOS.
- Users who want local settings/history and their own ASR/LLM credentials.
- Short and medium spoken input where the user can review the inserted result.

## What was actually verified for 1.0.5

- The current development candidate completed an owner-plus-computer-playback
  interference run: the recording capsule appeared, the owner track was kept,
  the final text was inserted, and the session reached `Done`.
- The exact candidate identity, executable hash, interference hash and operator
  result are recorded in
  [the 1.0.5 baseline evidence](evidence/20260909-current-interference-baseline.md).
- The current worktree passes `npm run build`, `npm test`, the documentation
  inheritance audit, the open-source hygiene audit, and the traceability check.
  Those are the checks that support this 1.0.5 product/documentation claim;
  they do not turn the private platform dependency into a public build.

## What is not a 1.0.5 promise

1.0.5 does not promise:

- perfect wake-up recall in every room, distance, accent or speaking style;
- perfect separation of every human speaker overlap;
- medical, legal, evidentiary or security-grade speaker identification;
- that every provider, target application or BLE host will accept direct text
  insertion;
- a self-contained public build while the pinned platform submodule remains
  private or unlicensed;
- that every firmware feature is available on every hardware revision.

The broader owner-enrollment and real-human interference work is intentionally
deferred to 1.0.6. This is a release boundary, not an invitation to silently
change 1.0.5 behavior.

## Before selling or publishing a branded build

Technical readiness is not the same as legal or distribution readiness. Before
selling a branded binary or changing the repository to public, the maintainer
must confirm:

1. the copyright holder and `LICENSE` text;
2. licenses and public read access for `third_party/denzic-platform` and all
   shipped model, firmware and icon assets;
3. signing certificates, update metadata and a reproducible release artifact;
4. a privacy notice covering provider-controlled cloud processing;
5. support and refund/upgrade terms appropriate to the sales channel.

The repository currently documents the platform dependency as **BLOCKED** in
[`docs/OPEN_SOURCE.md`](../OPEN_SOURCE.md). That status must be cleared before
calling the source tree a fully reproducible public open-source release.
