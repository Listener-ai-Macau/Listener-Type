# Listener Type 1.0.6 RC1 — build 9

Windows x64 release candidate, refreshed on **15 October 2026**.
The existing `v1.0.6-rc1` release now supplies build 9. It remains a
**prerelease** and does not replace the stable automatic-update channel.

## Install and matching firmware

- Download `ListenerType_1.0.6-rc1_x64_en-US.msi` and verify `SHA256SUMS.txt`.
  The MSI is **297 MB** (283 MiB). It upgrades earlier RC1 installers with the
  same version number. Existing settings and voiceprints are retained.
- Pair with [Listener Firmware 1.0.6 RC1](https://github.com/Listener-ai-Macau/Listener-Firmware/releases/tag/v1.0.6-rc1),
  build **`2be09b1ca730c7f3`**, for Listener keyboard-v2 / ESP32-S3 N16R8.
  The desktop's build number does not imply a new firmware image.
- Only the Windows MSI and its checksum file are supplied for Type.
  The installer and executable are unsigned; Windows may show a security prompt.
- Configure your supported recognition-provider credentials in Type.
  A hosted account/subscription service is not included. Development accounts,
  API keys, recordings and personal voiceprints are not release assets.
- The optional Chinese content-recovery model downloads into the per-user cache
  when enabled (approximately 890 MB). Ordinary cloud recognition does not wait
  for that optional model. Other bundled models and runtimes retain their
  license and attribution files.

## Fix in build 9

Fix a recording session that can remain active, leaving the device recording
light on after speech ends. Wake takeover can deliver retained audio before
the asynchronous VAD worker is ready; the old 64-packet queue treated that
normal burst as a permanent detection failure. The queue now bounds PCM bytes,
and a genuine overrun retires stale analysis and resumes fresh-source detection.
Skipped analysis remains unknown; original recognition/recording audio is kept.
Old in-flight inference cannot restore invalidated evidence. No body filtering,
silence threshold, forced recording timeout or new model is introduced.

The original saved recording reproduces the pre-fix failure and passes with
the corrected burst cadence. A separate forced-overrun replay recovers fresh
analysis without certifying skipped history. The installed executable matches
the MSI, with the main process and wake helper running. These checks do not
establish a new physical-light or full hardware/editor acceptance run.

## Included fixes from build 8

- Settle failed or unavailable editor receipts in both the input transaction
  and recording endpoint. A terminal failure no longer leaves an orphaned wait
  that can keep recording open. Failure is not treated as successful insertion
  or silence; current speech and unfinished text still protect recording.
- Break strong-reference cycles between the recognition session, its callbacks
  and coordinator. Finished/cancelled sessions can release their resources.
  The endpoint watchdog observes the owning session instead of keeping it alive.
- Observe Windows' paired Connected state during a long BLE link-loss backoff.
  An independently restored connection can reopen audio without waiting out the
  entire hold. Disconnected devices keep the existing power/idle policy.
- Treat an empty action shortcut as disabled during startup, settings updates
  and latch reset, rather than retrying an invalid registration every three seconds.
- Retain build 7's continuous enrollment reference: the session bank preserves
  the full original accepted phrase, including quiet internal speech and its tail,
  instead of reusing a compacted/repeated wake exemplar.

## Retained RC1 capabilities

Streaming raw text, continuation and final supplements share their original
recognized-source coordinates; eligible supplements retain punctuation.
The normal continuation window starts from actual final text delivery.
Voiceprint storage avoids Windows credential-size overflow. The preview capsule
can be hidden, moved and reset. Wake takeover preserves captured audio and
recording ownership, and ambiguous wake candidates use the existing helper check.
The smaller installer, on-demand recovery download and scoped encoder lifetimes
from earlier RC1 resource builds are retained.

## Evidence and remaining limits

Build 8 was installed on Windows on 15 October; its executable matches the MSI
payload, and the main process, wake helper and device audio stream were observed.
Two saved receipt-failure recordings passed the revised endpoint component
replay with the real local VAD. Checks also cover terminal receipt outcomes,
stale transaction ownership and callback resource release. The empty-shortcut
retry loop disappeared in the observed installed startup interval.

Saved replay does not establish a new full hardware/editor acceptance run.
Long-run memory savings and the new disconnect/reconnect branch remain subject
to field observation. Prior quiet-input, streaming, continuation and delivery
evidence is reused; builds 8 and 9 do not claim every daily-use defect is eliminated.

Strong external speech can still require a repeated wake command, foreign words
can remain, ordinary speech can false-wake, and persistent background speech can
still affect closing. Complete speaker isolation is not guaranteed. This build
adds no new anti-interference model and does not tighten body filtering or
change the closing timeout. Language support depends on the configured cloud
provider; global language and arbitrary overlap acceptance is incomplete.
