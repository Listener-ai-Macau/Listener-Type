# Listener Type 1.0.6 RC1

Speak into Listener and receive text at your cursor. This Windows x64 release
candidate preserves the current working streaming input while collecting the
recording, continuation, delivery and voiceprint fixes made since 1.0.5.

This is a **prerelease**, tagged `v1.0.6-rc1`. It does not replace the 1.0.5
stable automatic update channel. Pair it with
[Listener Firmware RC1](https://github.com/Listener-ai-Macau/Listener-Firmware/releases/tag/v1.0.6-rc1).

## Install

- Recommended installer: `ListenerType_1.0.6-rc1_x64_en-US.msi`.
- This release supplies the MSI installer only, as requested. The portable ZIP
  was withdrawn from the public attachments; archived local copies remain.
- The MSI is approximately 1.14 GB and includes the executable and model
  resources. `SHA256SUMS.txt` identifies the exact installer.
- The Windows installer and executable are **unsigned**. Windows SmartScreen
  may ask for confirmation on first installation.
- Configure your ASR provider credentials in Type. Accounts, API keys, saved
  recordings and personal voiceprints from the development machine are not
  distributed with the app. A hosted subscription/account service is not
  supplied by this candidate.

## What changed since the public 1.0.5 release

- Keep streaming speech and continuation aligned with the original recognized
  audio, so display cleanup does not consume later words or duplicate a final
  fragment. Preserve punctuation in eligible final supplements.
- Start automatic closing from the actual final text delivery receipt. New
  speech and still-pending personal text continue to protect the recording;
  editor failures do not count as silence.
- Save voiceprint templates without overflowing Windows credential limits.
  Recording and storage failures now show distinct guidance.
- Add a preview-capsule visibility setting, draggable placement and a reset
  position action.
- Keep local speaker observations separate from cloud recognition confirmation.
  Only sufficiently aligned other-speaker evidence excludes a foreign tail;
  incomplete or conflicting evidence keeps text to prioritize personal speech.
- Preserve captured audio and recording ownership during Listener wake takeover
  and BLE transport transitions.
- Cross-check ambiguous complete wake keywords against competing pronunciations
  on the same original audio, with a candidate-owned asynchronous helper task.

## Current limits and evidence

Quiet streaming, continuation, the final sentence and closing about three
seconds after actual final delivery have recorded real-device evidence. RC1's
second build adds an asynchronous wake-command cross-check to the original
beta.65-based runtime. The cross-check freezes the candidate and original PCM;
capture continues while a helper checks an ambiguous complete keyword. Matching
complete local intent takes the existing fast path. A conflicting pronunciation
can reject that one wake hypothesis only when both recognitions agree and the
native keyword coordinates refer to the same sound. The original audio remains
available for a later genuine wake command.

The retained ordinary-speech false wake passed both live and terminal candidate
completion paths through the actual helper protocol. One earlier whole-clip run
failed and its cause was not uniquely established; later instrumented runs
passed. This is targeted evidence, not a measured false-wake rate or new field
acceptance. An ambiguous wake may spend extra time in the cross-check; new
device latency remains unmeasured. No new model, enrollment or cloud service is
required. Text delivery and automatic closing logic were not changed.

The same-version MSI upgrade, installed running executable and portable payload
were checked on Windows. The installed helper also returned matching source-bound
conflicts for the retained failure's first 2.1 seconds and complete 9.4 seconds.
That check did not activate the microphone, editor or hardware control.

Interference remains **partially improved**. Strong external speech can require
a repeated wake command, some foreign text can remain, and ordinary personal
speech has produced a false wake. This candidate does not promise complete
speaker isolation or reliable wake in every noisy room. The second RC1 build
includes the targeted acoustic-competition repair;
ordinary speech without qualifying conflict evidence can still false-wake.

Language support depends on the configured recognition provider. Global
languages, short speech and arbitrary overlapping speakers have not all passed
field acceptance. This release supplies Windows x64 artifacts; it does not
claim new macOS or Linux package acceptance.

Review the preview and result before sending important text. Use the explicit
recording control if automatic wake is unreliable in the current environment.
