## 先用一句话理解 Listener Type

Listener Type 是一套本地优先的语音输入工具：它监听你指定的快捷键或 Listener BLE 语音键，把语音转成文字，按你选择的风格整理，然后插入当前光标所在的位置。

它不是只能“录音后导出”的转写器，而是一个可以每天使用的输入方式：

- 在聊天、邮件、文档、代码注释和表单里直接说，结果回到当前输入框。
- 用 **Raw / Light / Structured / Formal / Translation** 等输出方式，让同一段话适合不同场景。
- 电脑没有云端 Key 时，可以使用本地 ASR；润色服务不可用时，也会保留原始转写的可用回退。
- 配合 Listener 语音键盘，可以不用碰鼠标和屏幕完成开始、停止、取消和常用操作。
- 声纹、主人语音跟踪和干扰隔离共同减少旁人说话被写入正文，避免旁人声音拖长你的录音。
- 历史、词库、风格包和录音设置留在本机，云端只按你的配置处理必要的音频或文本。

## 1.0.5 适不适合购买或销售

从产品体验看，1.0.5 已经形成完整的日常输入闭环：快捷键或 Listener 设备开始录音、屏幕和灯光反馈状态、语音转成可编辑文字、结果回到当前光标，并在插入受限时保留剪贴板回退。当前版本还记录了一次“主人说话 + 电脑播放旁人语音”的完整通过路径，适合作为受控环境下的销售基线。

购买前仍需知道：

- Windows 是 Listener BLE 完整音频路径的主支持平台；macOS 可先使用电脑麦克风和快捷键。
- 云端 ASR/LLM 需要你自己的 Provider 凭据，服务质量和费用由对应服务商决定；也可以选择本地 ASR，但模型会占用磁盘和计算资源。
- 自动唤醒和干扰处理是输入保护，不是身份认证、取证或 100% 准确承诺。
- 当前完整开源构建仍受 `third_party/denzic-platform` 的公开许可证和访问权限影响，仓库状态为 **BLOCKED**；这不等同于已安装桌面体验不可用，但在解除边界前不应宣传成“单仓库即可复现的完整开源发布”。

更完整的购买/分发边界、已验证路径和 1.0.6 延期项见[1.0.5 发布边界说明](docs/release/1.0.5-commercial-readiness.md)。

## 30 秒第一次成功路径

### 只有电脑，没有 Listener 设备

1. 安装并启动 Listener Type。
2. 在系统权限里允许麦克风；macOS 另需允许辅助功能。
3. 打开「设置 → 录音」，选择麦克风和一个可用的 ASR 提供商，或准备本地 ASR。
4. 把光标放进任意文本框，按一次录音快捷键，看到屏幕底部胶囊进入 **Recording**。
5. 说一句话，再按一次快捷键；看到文字出现并插入光标位置。
6. 觉得结果偏口语、太散或需要翻译，再到「设置 → 录音」选择输出模式或翻译快捷键。

### 有 Listener 语音键盘

1. 给设备充电并开机。
2. 安装 Listener Type，在「设置 → 设备」或首次配对引导中点击「开始配对」。
3. 在 Windows 蓝牙设置中选择设备名 `listener`，等待软件显示已连接。
4. 默认使用设备语音键（产品流程通常标为 **KEY3**）或 **EC11 旋钮单击**开始/停止；第一次建议在记事本里试用。
5. 按键后看到 **REC**/胶囊录音状态，正常说话，再按一次停止；等待 **AI/Transferring** 完成，文字会进入光标。

## Listener Type 的核心特色

### 1. 说完就是可用文字

Listener Type 不把结果锁在自己的编辑器里。它会尽可能调用系统原生插入路径：Windows 优先使用 Listener Type TSF 输入法，其他情况使用剪贴板或系统粘贴回退；macOS 依赖麦克风与辅助功能权限完成全局输入。

如果目标软件禁止直接输入，结果仍会保留在剪贴板，并在胶囊或提示中告诉你需要手动粘贴。

### 2. 本地优先、自己选择服务

设置、历史、词库、风格包和大部分设备状态保存在本机。云端 ASR/LLM 使用你自己的服务商配置；应用不会内置开发者的 Key，也不会默认把录音上传到 Listener Type 自己的后台。

可选能力包括：

- 火山引擎流式 ASR。
- OpenAI 兼容批量 ASR。
- Apple Speech。
- 本地 Qwen ASR。
- Windows Foundry Local Whisper。
- Ark、DeepSeek/OpenAI 兼容、Anthropic 兼容及自定义 OpenAI 兼容润色端点。

本地 ASR 可以减少音频离开电脑的次数；但 Structured、Formal 和部分风格润色仍需要你配置的 LLM 服务，除非选择 Raw 或已有本地替代路径。

### 3. 给主人更可靠的自动唤醒和干扰处理

开启「检测到人声后自动开始」后，设备会等待你设置的唤醒词（默认“开始录音”）。录制声纹后，系统会用本机保护的声纹模板辅助判断是否是你本人：

- 声纹录入需要按引导自然说三遍唤醒词，总计约 9 秒。
- 原始录音只用于本机生成模板，完成后丢弃；不会把录音当作长期声纹文件保存。
- 没有录入声纹时，正确说出唤醒词仍可启动，但办公室等多人环境更建议录入。
- 主人说话时，旁人短暂插话不会直接覆盖主人正文；明确的旁人语音不会单独拖长自动结束。
- 这是降低误唤醒和干扰污染的工程保护，不是“任何噪声都能被消除”的承诺。距离太远、多人同时说话或麦克风被遮挡时，仍应靠近设备并重试。

### 4. 输出风格不是同一个“润色开关”

| 模式 | 适合场景 | 处理原则 |
| --- | --- | --- |
| Raw | 会议记录、代码、需要保留原话 | 最小整理，尽量保持顺序和措辞 |
| Light | 日常聊天、快速记事 | 去掉口癖和重复，补标点，不改变事实 |
| Structured | 让 AI 执行的任务、需求、Prompt | 按主题、目标、约束整理成结构化表达 |
| Formal | 邮件、工作沟通、对外文字 | 更正式清晰，不凭空扩写事实 |
| Translation | 双语沟通、外语输入 | 通过翻译快捷键把本次语音送入目标语言 |

### 5. 有一套可理解的硬件反馈

Listener 设备的灯、电脑屏幕上的语音胶囊和软件状态共同反馈当前阶段。你不需要看串口日志判断“有没有听到”：

- 胶囊显示 **Recording**：正在收音。
- 胶囊显示 **Transferring / Transcribing / Processing**：已经停止说话，正在传输、转写或整理。
- 设备的 **REC** 区域：录音状态；**AI** 区域：设备/主机正在进行 AI 处理。
- **BLE** 区域：蓝牙连接或就绪状态；**OK**：成功完成；**WARN**：错误或恢复提示；**PWR**：供电/电源状态。
- 低功耗时灯可能熄灭，这是省电行为，不代表设备损坏。

灯光亮度只是“让灯更容易看见”的设置，不代表声纹分数、麦克风音量、主人身份，也不决定什么时候自动结束。

## 安装、权限和平台

### Windows

- 支持 Windows 10 1903+ / Windows 11。
- 安装 MSI 后，Listener Type 会注册 Windows TSF 输入法，用于提高受限软件中的文字插入成功率。
- 使用 Listener BLE 设备的完整 BLE 音频路径当前以 Windows 为主；如果设备选项显示不可用，请使用电脑麦克风或查看版本/固件支持。
- 需要允许麦克风、全局快捷键监听；若系统提示，按说明打开相应权限。

### macOS

- 目标版本为 macOS 12+。
- 需要允许麦克风和辅助功能；授权后通常要完全退出并重新打开 Listener Type。
- 没有 Listener BLE 时，可以直接使用电脑麦克风和全局快捷键。

### 网络与凭据

第一次使用云端 ASR 或 LLM 时，需要在「设置 → 提供商」填入你自己的凭据，并用「验证」确认服务可用。遇到国内服务商连接问题，优先把该服务商的 Network 设为 **Direct**；需要代理的服务再选择 **System proxy** 或自定义 HTTP proxy。

如果你只想本地识别，可在「设置 → 本地 ASR」准备 Qwen 或 Windows Foundry Local；首次下载本地模型会占用磁盘和时间。

## 桌面端怎么用

### 录音快捷键

默认是切换式：按一次开始，按一次结束，不需要一直按住。

- Windows 默认：右 Control（Right Control）。
- macOS 默认：右 Option（Right Option）。
- 可以在「设置 → 快捷键」改成其他组合键或自定义组合。
- 录音中或处理中按 `Esc`：取消当前会话，不插入本次结果。

把光标先放到目标输入框，再按快捷键。若光标离开、目标窗口拒绝自动输入或权限不足，先看胶囊提示，再从剪贴板粘贴结果。

### 录音设置

在「设置 → 录音」可以调整：

- 输入源：电脑麦克风或 Listener BLE。
- 首选麦克风：断开时自动回退到系统默认。
- 录音胶囊：是否显示屏幕底部的状态胶囊。
- 录音时静音：临时静音系统输出，减少扬声器回音。
- 检测到人声后自动开始：监听唤醒词。
- 检测不到人声后自动结束：本人停止说话约 1 秒后结束；旁人说话不应单独拖长。
- 唤醒词：最多 16 个字符；修改后需要重新录制声纹。
- 仅本人语音自动开始：进入三步声纹录入。
- 词库、历史保留、原始调试录音和插入/剪贴板回退选项。

### 翻译、风格和划词问答

- 在「翻译」里设置工作语言和目标语言；录音过程中按翻译快捷键，当前会话走翻译管线。
- 在「风格」里启用 Raw、Light、Structured、Formal 或本地自定义风格包。
- 在其他应用选中文字后，按划词问答快捷键打开问答浮窗；浮窗内继续使用主听写键提问，可以多轮追问。
- 历史记录保存最近会话的原文、输出模式、润色结果和供应商信息；原始录音是否保存由高级设置控制。
- 词库适合加入人名、产品名、缩写和专业词；启用后会作为 ASR 热词和润色提示。

## Listener 语音键盘：按键、旋钮和灯怎么用

### 上电与配对

1. 用 USB-C 充电，首次使用建议先让设备有足够电量。
2. 旋转/按下 EC11 进入开机路径；设备名默认为 `listener`。
3. 在 Listener Type 的「设置 → 设备」点击「开始配对」，再在 Windows 蓝牙列表选择 `listener`。
4. 软件显示已连接后，回到「设置 → 录音」检查 Listener BLE 音频通路。
5. 搜索不到设备时，先按设备的唤醒键（通常是 KEY4），仍无效再删除 Windows 中旧的 `listener` 记录并重新配对。

### 设备按键语义

| 控件 | 默认用户动作 | 能否自定义 | 固定/注意事项 |
| --- | --- | --- | --- |
| KEY3 / 设备语音键 | 开始 / 停止语音输入（产品默认录音路径） | 可以在设备自定义键里改成其他动作 | 它是硬件录音体验的常用入口；低层 fallback 是 KEY3 单击 `F15` |
| KEY1 | 常用快捷键入口；未改时走桌面默认映射 | 可以 | 单击/双击/长按分别有独立配置 |
| KEY2 | 默认可作为复制快捷键入口 | 可以 | 单击/双击/长按分别有独立配置 |
| KEY4 | 唤醒/恢复设备的常用按键，也可配置动作 | 可以 | 设备离线时先按 KEY4，再重试 BLE 检查 |
| EC11 单击 | 开始 / 停止录音 | 可以 | fallback 为 `Shift+F13`，不要改成 F25 |
| EC11 双击 | 重置蓝牙并重新进入配对路径 | 固件固定 | 这是恢复动作，不是普通自定义键 |
| EC11 长按 | 关机/电源路径 | 固件固定 | 长按不要当作录音键连按 |
| EC11 旋转 | 默认调电脑音量 | 可以 | 可改为屏幕亮度或禁用 |

> KEY3 是产品语音键路径；桌面端也存在一套“自定义键收到 fallback 热键后做什么”的映射。两者不要混为一谈：设备固件负责发出物理手势，Listener Type 负责把它映射成录音、复制、打开页面等动作。

### 自定义键在哪里设置

打开「设置 → 设备 → 设备自定义键」。每个按键可以按 **单击 / 双击 / 长按** 分开配置；EC11 的双击和长按由固件固定，旋转在「旋钮动作」单独设置。

可选动作包括：

- 无（禁用）。
- 开始 / 停止录音。
- 发送按键或快捷键。
- 复制 `Ctrl+C`、粘贴 `Ctrl+V`、撤销 `Ctrl+Z`。
- 打开软件页面：总览、历史、词库、风格、翻译、划词问答、设备/录音/供应商/快捷键/权限/语言/高级设置。
- 打开指定应用或快捷方式。
- 粘贴模板文字。
- 切换到上一个风格。
- 翻译听写。
- 划词问答。

恢复「设备自定义键」时，当前桌面端默认输出映射为下面这样。它表示 Listener Type 收到对应 fallback 热键后执行的动作，不覆盖上一张表里的固件物理语义：

| 入口 | 默认桌面动作 |
| --- | --- |
| KEY1 单击 | 发送 Right Control |
| KEY2 单击 | 发送 `Ctrl+C` |
| KEY3 单击 | 发送 `Ctrl+V` |
| KEY4 单击 | 发送 `Ctrl+Z` |
| EC11 单击 | 开始 / 停止录音 |
| KEY1-KEY4 双击/长按 | 默认禁用 |

如果要把 KEY1-KEY4 当作设备按键 fallback 入口，Listener Type 使用以下保留矩阵：

| 设备手势 | KEY1 | KEY2 | KEY3 | KEY4 |
| --- | --- | --- | --- | --- |
| 单击 | `F13` | `F14` | `F15` | `F16` |
| 双击 | `F17` | `F18` | `F19` | `F20` |
| 长按 | `F21` | `F22` | `F23` | `F24` |

EC11 单击的 fallback 是 `Shift+F13`。这些键位由 Listener Type 保留；不要把普通自定义快捷键设置成 F13–F24 或把 EC11 改成 F25，否则会与设备动作冲突。

### 灯光和亮度怎么调

在「设置 → 设备 → 灯区亮度」分别调整 0–100 的最大亮度：

| 灯区 | 包含内容 | 你会用它判断什么 |
| --- | --- | --- |
| 状态灯 | PWR / BLE / REC / AI / OK / WARN | 电源、连接、录音、处理、成功、警告 |
| 按键灯 | KEY1–KEY4 | 按键位置和按键反馈 |
| 旋钮灯 | EC11 环灯 | 旋钮位置和交互反馈 |
| 板框灯 | 边框氛围灯 | 环境可见性和产品状态氛围 |

写入亮度前，确保设备已连接且固件支持四区亮度回读。若软件提示当前固件不支持，先更新固件；不要通过反复点击写入按钮解决。亮度是上限，不会改变录音灵敏度、声纹判断或自动结束规则。

### 低功耗和供电

- 插电模式和电池模式可以分别设置进入低功耗的等待时间。
- 电池模式进入低功耗时通常会灭灯，这是正常省电行为。
- 插电模式可以关闭低功耗，让设备保持活跃连接和灯状态。
- 电池模式还可以设置长时间空闲后的自动关机。
- 设备要做 OTA 或长时间配置时，建议保持 USB 供电、暂停录音并等待设备回到 Ready。

## 状态怎么读

| 软件/设备状态 | 意思 | 你应该做什么 |
| --- | --- | --- |
| Ready | 可以开始录音 | 按录音快捷键、KEY3 或已配置的录音键 |
| Recording | 正在收音 | 正常说话；说完再按一次停止 |
| Transferring | BLE 音频正在传到电脑 | 不要连续按键，等待文字 |
| Transcribing / Processing | 正在转写或润色 | 等待胶囊完成；需要放弃时按 `Esc` |
| Done / OK | 已完成并尝试插入 | 在目标输入框检查文字 |
| Error / WARN | 当前连接、权限、服务或插入失败 | 按错误提示处理，必要时重试或导出诊断 |
| Recovery | 正在重连或等待重新配对 | 按 KEY4/唤醒键，或删除旧蓝牙记录后重新配对 |

屏幕胶囊里的音量条只表示当前音频能量和可见反馈，不代表“这是主人声音”，也不代表“马上应该结束”。真正的唤醒、主人识别和结束由会话状态机、声纹/说话人证据和 ASR 共同决定。

## 常见问题和恢复路径

| 现象 | 先做什么 | 仍失败怎么办 |
| --- | --- | --- |
| 按键完全没反应 | 检查麦克风/辅助功能权限和录音快捷键是否被其他软件占用 | 打开「设置 → 权限」查看全局监听状态；重启 Listener Type |
| 录音胶囊出现但没有文字 | 检查 ASR 凭据、网络、麦克风输入源或本地模型状态 | 先切 Raw；验证服务商；改用本地 ASR；导出诊断包 |
| 文字出现但没有插入 | 确认目标窗口仍有光标 | 手动从剪贴板粘贴；Windows 检查 Listener Type TSF 输入法是否安装 |
| 旁人说话进入正文 | 录制声纹、靠近设备并减少同时说话 | 检查是否误把非主人语音当唤醒词；不要仅靠调大灯光解决 |
| 录音一直不结束 | 先按一次停止键或 `Esc` 取消 | 检查「检测不到人声后自动结束」；保存诊断后重试，不要连续点击多个入口 |
| 搜索不到 `listener` | 给设备充电并按 KEY4/唤醒键 | 删除 Windows 旧配对记录，在「设置 → 设备」重新配对 |
| 配对后 BLE 检查失败 | 关闭其他占用设备的工具，保持设备靠近电脑 | 设备恢复路径：停止当前会话 → 删除 `listener` → 重新配对 |
| 设备有灯但软件显示离线 | 灯可能只是电源或低层状态，不等于 BLE 音频已就绪 | 在「设置 → 录音」重新检查 Listener BLE；必要时导出诊断包 |
| 云服务只在某个网络下失败 | 检查该 Provider 的 Network 设置 | 国内直连服务优先试 Direct；代理服务试 System proxy/自定义 HTTP proxy |
| Marketplace 没有内容 | 这是本地优先默认行为 | 只有配置 Listener Type 后端后才启用远程市场；本地风格包不受影响 |

### 设备恢复的推荐顺序

1. 停止或取消当前录音，等待胶囊回到 Idle/Ready。
2. 关闭其他可能占用 BLE 的工具。
3. 按 KEY4/唤醒键，让设备重新广播。
4. 在 Windows 蓝牙设置删除旧的 `listener` 节点。
5. 回到 Listener Type「设置 → 设备」重新开始配对。
6. 连接成功后，在「设置 → 录音」检查 Listener BLE 音频通路。
7. 如果仍失败，打开「设置 → 关于 → 导出诊断包」，附上复现步骤、版本和安装包哈希。

诊断包用于定位连接、订阅、会话和设备状态，不应包含录音、转写正文、插入文本、API Key、访问令牌或 OAuth 令牌。它不能替代设备固件的物理恢复出厂；固件长按恢复属于独立的硬件流程。

## 隐私、安全和边界

- API Key 保存在本机配置或系统凭据存储中，不要把 Key 写进 README、截图或诊断包。
- 云端 ASR/LLM 是否接收音频或文本取决于你选择的 Provider 和功能；Raw + 本地 ASR 可以减少云端处理。
- 历史和调试录音由「历史保留天数」「保留原始录音」等设置控制；开启调试录音后，原始 WAV 会明确落盘，请按隐私要求关闭或及时清理。
- 声纹模板只用于本机主人判断；它不等同于身份认证、门禁或安全登录。
- Listener Type 不是医疗设备、录音取证工具、儿童看护工具或保证 100% 准确的会议记录服务。
- 自动唤醒和干扰处理应理解为输入保护：它减少误触发、旁人污染和错误收尾，但嘈杂环境仍需要合理距离和复核结果。

## 几个容易忽略、但很值得打开的能力

### 流式输入：先看到结果，再等完整结果

在「设置 → 高级」打开「流式输入」后，符合条件的润色结果会边生成边落到光标，减少等待感。它只对支持的 OpenAI-compatible LLM 和可直接输入的目标窗口生效；Raw、翻译、Secure Input 焦点以及不兼容的服务会自动回退到一次性插入，不会让这次听写卡死。Wayland 下流式输入会关闭，并保留结果到剪贴板供手动粘贴。

可以单独打开「同步到剪贴板」：流式插入成功后把最终文本留在剪贴板，方便再次粘贴；关闭时流式过程不会改动剪贴板。

### 剪贴板策略可以按工作习惯选择

在「设置 → 高级」可以选择：

- 「转写保留到剪贴板」：每次普通听写完成后把最终文本留在剪贴板，优先级高于恢复旧剪贴板。
- 「插入后恢复剪贴板」：成功粘贴后恢复原来的剪贴板内容；当前仅 Windows / Linux 支持。

如果目标应用拒绝自动输入，结果仍会尽量留在剪贴板；这不是转写失败，而是目标窗口的输入策略不同。

### 翻译和工作语言

当前工作语言支持简体中文、繁体中文、English、日本語、한국어。翻译模式需要在设置里选择目标语言，录音时按翻译快捷键；翻译服务失败时会回退为原始转写，避免整次输入丢失。

界面语言还支持「跟随系统」、简体中文、繁体中文、English、日本語和한국어。语言切换只影响界面，不会替你改变已经配置的 Provider 或快捷键。

### 划词问答的隐私边界

划词问答只把当前选中的文本放在内存里，浮窗关闭后释放，不写入普通历史正文；是否保存问答元数据由单独的历史开关控制。选中文本超过 4000 字符时，会只取开头 2000 和结尾 2000 再发送给已配置的 LLM。适合先选一段文字再追问、改写或解释，但仍应把选区视为可能发送给 Provider 的数据。

### 本地风格包与远程市场是两回事

内置和导入的风格包可以离线使用，风格包、词库、历史和设置都保存在本机。Marketplace 默认可能为空，这是本地优先策略，不代表风格功能坏了；只有配置 Listener Type 后端并完成相应 GitHub 登录后，远程上传、点赞等能力才会出现。不要为了使用本地风格包而配置不需要的云端服务。

### 固件升级前先看清条件

设备设置里的固件升级入口会先检查设备型号、版本、校验值、连接状态和当前是否正在录音。Listener BLE OTA 当前以 Windows 为主；部分构建还提供 USB / 有线刷写入口，是否显示取决于硬件和固件包。升级时请：

1. 停止或取消录音，等待状态回到 Ready。
2. 使用包含校验信息的官方固件包，不要改名或手动替换包内文件。
3. 保持设备 USB 供电、靠近电脑，不要在传输中关机或拔线。
4. 等待设备重启、重新连接并完成版本确认；如果版本没有确认，不要连续重复刷写，先导出诊断包。

### 启动与更新是可控的

可以打开「启动时静默运行」，让应用只在菜单栏 / 系统托盘工作，不弹主窗口。自动更新检查在本地优先构建中默认关闭；关闭时仍可在「关于」中手动检查，打开后会在启动和之后每 60 分钟检查 Listener Type 发布通道。这样既不会偷偷改变工作环境，也保留明确的升级入口。

### 关闭、退出和“又自动起来”怎么区分

- Windows 标题栏右上角的 **X** 默认是“隐藏主窗口”，不会结束 Listener Type；这是为了让全局快捷键、设备语音键和托盘菜单继续可用。要真正退出，请右键托盘图标选择「退出 Listener Type」，或在安装目录运行 `listener-type.exe --quit`。
- 「开机自启」是独立的系统开关。打开后，Windows 会在用户登录时从 `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run` 启动 Listener Type；它不会因为本次点击“退出”而自动关闭。若不希望登录后自动出现，请在「设置 → 录音 → 启动 → 开机自启」关闭。
- 如果是**设备**长按旋钮关机后马上又亮起，优先更新到与当前 1.0.5 good 基线对应的固件包。插电关机路径会主动断开 ESP32-S3 USB Serial/JTAG 数据 PHY，避免电脑的 DTR/RTS 探测被芯片误当成复位；只有关机失败回退时才重新接回数据 PHY。旧的 8 月 OTA 包没有这条修复，不能用于判断当前版本行为。
- 仍然重复启动时，先确认任务管理器中的路径只有 `C:\\Program Files\\Listener Type\\listener-type.exe`；主进程旁边的 `--local-wake-helper` 是正常的本地唤醒辅助进程，不是第二个应用实例。

### 录音保留和调试录音要分开理解

历史保留天数、历史条数、润色上下文窗口和原始调试录音是不同设置。调试录音用于排查麦克风、BLE 或干扰问题，会把原始 WAV 写入本机；隐私敏感场景建议默认关闭，并在问题定位后及时清理。诊断包默认不含录音、转写正文、插入文本或凭据，但可用的调试音频样本应按页面提示单独确认后再提供。
