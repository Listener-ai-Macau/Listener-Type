# Support

Use GitHub Issues for reproducible Listener Type defects and feature requests. Before opening an issue, update to the latest release and check whether the behavior is listed under **Product status** in the README.

## A useful bug report

Include:

- Listener Type version and operating system
- computer microphone or Listener keyboard input
- recognition provider and writing style, without credentials
- target application and exact steps to reproduce
- expected result and actual result
- firmware version and Bluetooth state when the keyboard is involved
- a short, redacted log excerpt or exported diagnostic package when available

For recording, wake, automatic-ending, or interference defects, also describe what the owner said, when speech stopped, what background audio continued, and which text was incorrectly kept or lost. Attach audio only when every recorded person has consented.

## Protect private data

Remove API keys, access tokens, personal transcripts, recordings, names, device identifiers, and unrelated application content. Diagnostic exports should be reviewed before upload.

Report security vulnerabilities privately through GitHub Security Advisories as described in [SECURITY.md](SECURITY.md).
