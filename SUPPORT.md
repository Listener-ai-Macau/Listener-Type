# Support

## Before opening a request

1. Read the [中文产品手册](README.zh.md) or [English usage guide](docs/USAGE.md).
2. Check [installation and permissions](docs/quickstart/installation.md) and the
   [recovery guide](docs/features/ble-customer-recovery-diagnostics.md).
3. Search existing GitHub issues before opening a duplicate.

## Where to ask

- Use the **Question / support** issue form for setup questions and expected
  behavior.
- Use the **Bug report** issue form for a reproducible defect.
- Use the **Feature request** issue form for a concrete product proposal.
- Use a private GitHub Security Advisory for a vulnerability. Do not publish
  credentials, recordings, transcripts, diagnostic exports, or personal data.

## Include only useful, safe context

Include the app version, operating system, whether the issue uses the computer
microphone or Listener BLE, the output mode, and minimal reproduction steps.
Redact API keys, access tokens, device identifiers, personal names, recordings,
transcripts, and full local paths before attaching logs or screenshots.

Listener Type is local-first, but cloud ASR/LLM behavior depends on the provider
you configure. Provider outages, account limits, and unsupported target apps may
not be defects in Listener Type.
